Saved workflows: what happens after a file is saved

The roadmap says: simple "after download" actions first (extract audio, compress for Discord, move to a folder), a builder only if people want chains like download → clip → 9:16 → compress, and a watched folder that compresses or converts whatever lands in it. Neria already does each step on its own (Compress's goals, Sound only, Make a GIF, Transcript). A workflow just remembers a pair of them under a name and runs them without asking. Five questions below, one option marked PICK in each (my recommendation; nothing is built yet).

Ground rules

What a workflow is, and what it isn't

  • One change, then one place. "Make it smaller for Discord, then put it in Clips". Every step is something a page already does, with the same words (Compress's goals, Sound only's formats, Make a GIF).
  • The original stays unless you say so. The default makes a copy next to it, as Compress does. "Replace the original" is a choice you make in the workflow, in plain words, never the default.
  • It runs in the queue, on the download's own row. No second row, no new screen to watch. A step that fails leaves the download saved, with a note (as a transcript that fails does today).
  • Three to start with, so it's useful before you make one: Discord-ready (smaller for Discord, a copy), Sound only (MP3, a copy), Into a folder (moved to a folder you pick). Edit or delete them freely.
  • No new page. Picked on the Download page, kept in Settings, run on files from the Library and the palette.
1 · Picking one for a download

Where you say "and then…"

1A · A "Then" button in the row under the quality chips, beside Transcript PICK

It reads what will happen ("Then: Discord-ready") before you press Download, the same way the captions and Transcript buttons do. It opens a short menu: your workflows, Nothing, New workflow…. A workflow that runs by itself for this link (section 3: "every download", or "TikTok links") shows already picked, and the menu says why, so it's never a surprise. A pick is for this link only; the next link starts from Nothing (or from the automatic one).

3 · When it runs

Picked by hand, or by itself

3A · "When" is part of the workflow PICK

One list to understand, not workflows plus rules. The choices:

Two automatic ones for the same link: the more specific wins (TikTok links over Every download), and the Then button shows which one it picked. Nothing ever runs two workflows on one file.

3B · Workflows, plus a separate list of rules ("TikTok links → Discord-ready")

More flexible (one workflow, many rules), but two lists to read to know what happens, for a case nobody has yet.

4 · The watched folder

Files dropped in a folder get a workflow

4A · A workflow's "When: for files put in a folder" PICK

Pick the folder; anything that lands there (from your phone's sync, OBS, a browser download) gets the workflow, in the queue like a download. The results go in a Done folder inside it (so they're never picked up again), originals stay where they are unless "Replace" was chosen. Neria waits until a file stops growing, skips half-finished ones (.part, .crdownload, .tmp) and files it made itself, and does a file once (remembered by name, size and time). Files already in the folder when you turn it on are left alone, with a "Do the 12 already there" button. Runs while Neria is open or in the tray; the tray says so.

4B · A "Watch a folder" switch on the Compress page

Close to the work it does, but it would use whatever goal the page has at the time: change the goal for one file and the folder quietly changes too. And it couldn't move files or make GIFs.

5 · Where they're kept

Settings → Workflows, and run from anywhere

5A · A Workflows section in Settings, after Following PICK

Each row: the name, what it does in one line, when (yellow when it runs by itself), a switch to pause an automatic one, Edit. The watched folder's row says what it's done. On files you already have: a Library row's ⋯ and the picked-rows strip get Run a workflow…; the palette finds each workflow by name ("discord-ready" → which file).

6 · While it runs

In the queue

6A · The download's own row carries on PICK

The row says the step it's on, with dots for the steps. Done, it names the workflow and the result; Show file opens the result, ⋯ has Show the original. Both are in the Library; the result's details say "Made by Discord-ready from …". A step that fails: the download is still saved, the row says what didn't happen, with Try again.
