External tools: your own programs as Neria actions

The roadmap: instead of a plugin system, people who already use command-line programs (HandBrake, Real-ESRGAN, ffmpeg with their own recipe, a script of theirs) add them as actions, with blanks like {file} and {out} that Neria fills in. They run in the queue like everything else. Nothing is loaded into Neria and nothing is bundled: Neria starts the program you point it at, with the words you typed, and shows what it says. Five questions; one option each marked PICK.

Ground rules

What a tool is, and what it isn't

  • A program, its words, and blanks. HandBrakeCLI.exe -i {file} -o {out} --preset "Fast 1080p30". Neria fills the blanks with quoted paths and starts the program itself, never through a shell (no cmd /c, so a file named a&b.mp4 can't run anything).
  • Only what you set up. No tool comes with Neria, none is fetched, none can be imported from a link. A tool runs when you pick it, or from a workflow you made.
  • A copy unless you say otherwise, as everywhere else: {out} is a new name next to the original, never the original itself.
  • In the queue, with what it says. The row shows the program's last line while it works; a failed run keeps all of it (Copy the report), with the exact command it ran.
  • For people who know what a command line is. It lives in Settings, out of everyone else's way; nothing on the main pages changes until you add one.
1 · Where tools show up

Their own list, or a kind of workflow step

1A · A list in Settings → Tools, and each tool is also a workflow change PICK

You make a tool once. It then shows where Neria's own actions do: a Library row's menu (Run a tool ▸), the picked-rows strip, the palette ("upscale" → which file), and as a Change it choice in a workflow, so "every TikTok: run Upscale 2×, into D:\Edits" or a watched folder through HandBrake just works. One place to make them, everywhere to use them.

1B · Only inside workflows ("Change it: run a command…")

One concept fewer, but running HandBrake on one file means making a workflow for it, and the same command typed into three workflows is three copies to keep in step.

1C · Only as actions (Library, palette), not in workflows

Simpler to build, but the most useful case (every download or a watched folder through your tool) is gone.

2 · Making one

The tool editor

2A · A form: program, words with blank chips, what it makes, and the command it'll run PICK

Pick the program (a file picker; a name like ffmpeg finds it on PATH or in Neria's own bin). Type its words; the blank chips under the box add a blank where the cursor is. It makes says whether there's a new file (and its kind) or nothing (a tool that uploads, tags or opens something). The last box is the real command, filled in for a sample file, so you see exactly what will run before you save. Try it on a file… runs it once and shows what it printed.

2B · One box: the whole command line

Quickest for people who paste from a forum post, but then Neria has to split a command line the way a shell would (quotes, carets), and a pasted cmd /c … && del … just runs. 2A can still take a paste: pasting a whole line into Program splits it into the two boxes, once, where you can see it.

2C · Start from examples (HandBrake, Real-ESRGAN, ffmpeg loudnorm…)

Friendly, but they'd be Neria naming and vouching for programs it doesn't ship or check. Could come later as a "Examples" link to a page of copyable words, not as one-click tools.

3 · Several files

One run each, or one run for all

3A · One run per file, always PICK

Each file is a queue row of its own: its own progress, its own failure, Cancel one. Picking 5 rows and Run a tool makes 5 runs, one after another (two at once at most, like downloads). Nearly every command-line media program takes one input.

3B · Also a {files} blank: all of them in one run

For programs that join or compare (a "concat" script). Rare, and a run that fails takes all of them with it. Later, if someone asks.

4 · While it runs, and when it fails

In the queue

4A · Its row shows the program's last line; a failure keeps what it said PICK

Neria can't know a foreign program's progress, so the bar moves only when the program prints a percentage (42% or 42.0% anywhere in a line), else it's the busy stripe. Done: the new file, Show opens it, and it's in the Library ("made by Upscale 2×"). It made no file, or quit with an error: the row says which, with its last lines and Copy the report (the exact command and everything it printed). Cancel ends the program and everything it started. No window pops up (programs start hidden); a program that needs a window (an editor) belongs to "It makes: Nothing", which starts it and moves on.

4B · Open a console window for each run

You'd see everything, but a black window per file, popping over the game you're playing, is exactly what Neria avoids.

5 · Keeping it safe

A tool can do anything its program can

5A · No shell, the command shown before it's saved, and a tool only runs on its own once you've tried it PICK

  • The program is started directly with its words as separate pieces; blanks are filled with paths, never pasted into a line a shell reads.
  • "It'll run" shows the real command before Save. Changing a tool that a workflow uses shows "Used by Every TikTok" so you know what you're changing.
  • A tool can be picked for a workflow that runs by itself (every download, a watched folder) only after it has run once by hand (Try it, or from the Library) and finished, so a typo doesn't hit 40 downloads overnight.
  • Tools live in tools.json next to the exe like everything else; there's no import, no link that adds one.
Runs only after you've tried it once: Upscale 2× hasn't run yet. Try it on a file first, then pick it here.

5B · Ask "Run this program?" before every run

Safe-sounding, but a question per file trains everyone to click Yes, and it can't ask at 3 AM in a watched folder.
