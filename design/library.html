Library: everything Neria saved, in one place

Today what Neria made is scattered: the queue forgets finished rows once cleared, Capture's Saved list keeps the last 8, Clip and Compress show 5 "Recent downloads", and a compressed file or a GIF isn't remembered at all. The Library is one list of everything Neria has saved (downloads, link clips, clips from files, live recordings, instant replays from the PC and the phone, compressed files, GIFs, transcripts, Spotify songs and playlists) that you find, reopen and do the next thing with: watch it, clip it, compress it, transcribe it, get it again. Calm like the queue, because you read it; the actions are the playful part.

Chosen 2026-11-23: 1A, 2A, 3A, 4A + 4B, 5A (the PICKs below; 2B's grid only later, as a view switch).

Ground rules

What it is, and what it isn't

  • Only what Neria saved. Not a media manager for the whole Videos folder: no scanning drives, no "add a folder". That keeps it fast, honest ("Neria made this") and portable (one library.json next to the exe).
  • It doesn't move or rename files. Files stay where they were saved. If one moves, the Library says Gone and helps find it; it never deletes a file unless you ask, and then to the Recycle Bin.
  • Each item knows where it came from: the link (so "Download again" works), or the file it was made from (a clip, a compressed copy, a GIF), and what's attached next to it (.chat.json, a transcript, captions). Those show as small marks on the row and as a list in the item's details.
  • Existing users don't start empty. On first open it fills itself from history.json, Capture's Saved list and Spotify folders' .neria-sync.json (see the last section for what's there today).
  • The queue stays the place for what's happening now. The Library is what's done. A finished queue row gets "In Library" through its ⋯ menu, nothing more.

Library sits last of the pages because it's where things end up. On compact windows the bar keeps five tabs (Download, Clip, Compress, Capture, Library) and Settings becomes a labelled gear icon at the right of each page's header, next to the logo and headline (header buttons already go icon-only there, DESIGN.md). Settings is opened rarely; the Library daily. Five tabs at 400 px are 78 px each, the same as today.

2 · How items look

Calm rows, or a thumbnail grid

Both share the top of the page: headline, search (Ctrl+F or just start typing), filter tabs by kind with mono counts (as the queue's, since they change the view), and two menu buttons, Site and Date, plus Sort. A menu button that's been set gets the "set" outline, and "Clear" appears.

2A · Rows grouped by day, a details column on the right PICK

Queue rows you already know (60 px, 64×36 thumbnail, title, a status line) under day headings. The line says kind · site or source · length · size, then small marks for what's attached (chat, transcript, captions). Songs get a square cover. A Spotify playlist is a group card: one row, a stacked cover, "48 songs", Update playlist. Rows show Watch and Clip on hover; the selected one fills the details column (section 3). Works for every kind, including sound files and transcripts, which have no picture to show in a grid.

3 · Each item's actions

What you can do next, by kind

One yellow action per page: Watch (Play for sound) in the details column, in Neria's own player. Everything else is ghost buttons and the ⋯ menu. What's offered depends on the kind and on what's possible: no Download again without a link, no Transcribe when a transcript is there (it becomes Open transcript).

3A · Details column on wide, the row opens in place on medium, a sheet on compact PICK

The ⋯ menu holds the rest, the same on every width. Delete file sends it to the Recycle Bin and asks first; Remove from Library only forgets it.

4 · Missing files and a first visit

Gone, found again, and nothing yet

4A · Gone stays in the list, with a way back PICK

The Library checks files when it opens (in the background; a missing drive isn't "gone", it's "On drive E:, not connected"). A gone item keeps its row, greyed, with a Gone tag and the way back that fits: Find it… (pick where it went; Neria then looks for the others from the same folder there and says how many it found), Download again when there's a link, or Remove. A calm banner sums it up once there are several, and a Gone filter tab appears (amber count) only while there are any.

Underneath

What's remembered today, and what the Library needs

From the code as it is now. Most kinds are already saved somewhere; few are remembered as "this thing, made from that". The plan: one library.json next to the exe (records with kind, source, site, length, size, attached files), filled once from what's below, then written where each thing is saved. JSON is still enough at a few thousand records (history keeps 5,000), so no SQLite.
